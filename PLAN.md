## Milestone 8: Fix real-run crash — generation width/height not divisible by 8
Bug (reproduced, still unfixed as of the 2026-10 audit): `Pipeline.run()` (`src/pageloom/pipeline.py:75-76`) sets the Stable Diffusion generation width/height directly from `self.style.get("composition", {}).get("page_dimensions", ...)`, which is derived from the example image's raw pixel size (`style_extractor.py:80,96`, `page_structure_classifier.py:32`) with no rounding. Diffusers' VAE requires both dimensions to be a multiple of 8, or `check_inputs()` raises `ValueError`. Reproduced end-to-end with a real run: `uv run pageloom generate --pages 1 --example letter-a-writing-practice-worksheet-618x800.jpg --use-llm --output out.pdf` crashed with `ValueError: height and width have to be divisible by 8 but are 800 and 618` (618 ÷ 8 = 77.25), traced through `pipeline.py:206` → `generator.py:73` → `diffusers/pipelines/stable_diffusion/pipeline_stable_diffusion.py:639`. No existing test catches this: every integration test uses a `MagicMock` generator whose `side_effect` ignores whatever width/height it's called with, so the real diffusers dimension check is never exercised; even the hardcoded fallback default (612×612 in `pipeline.py:75-76`) is not divisible by 8 (612 ÷ 8 = 76.5) — a general bug, not specific to one image.
- [x] Fix: round width/height to the nearest multiple of 8 (e.g. `((dim + 7) // 8) * 8`, or round down to avoid growing past the source aspect ratio too much) before passing to `IllustrationGenerator.generate()`. Audit every place `page_dimensions` is derived from an example image and feeds into a real (non-mocked) diffusers call — `style_extractor.py` writes `page_dimensions` and `pipeline.py` consumes it, and the multi-sub-image path (`pipeline.py:117-136`) computes `max(150, ...)` sub-dimensions that are also generally not multiples of 8
- [x] Add a regression test that does not mock away the bug: either unit-test the new dimension-rounding helper directly with known odd inputs (e.g. 618×800 → both outputs divisible by 8), or update an integration test's mock generator to assert it was called with `width % 8 == 0 and height % 8 == 0`, so this class of bug can't silently regress again
